## D-001 · 린터를 oxlint에서 ESLint로 교체

**결정일** 2026-08-01

**문제** Vite 스캐폴드 기본 린터가 oxlint였다. 속도는 빠르지만 이 프로젝트에서
실제로 났던 결함을 잡는지 확인되지 않았다.

**근거** 이전 프로젝트에서 난 결함 4종을 재현해 두 린터를 대조했다.

| 결함 | oxlint | ESLint (react-hooks v7) |
|---|---|---|
| `rules-of-hooks` 조건부 훅 | O | O |
| `static-components` 렌더 중 컴포넌트 정의 | **X** | O |
| `purity` 렌더 중 `Date.now()` | **X** | O |
| `set-state-in-effect` | **X** | O |

`static-components`는 입력창을 매 렌더 리마운트시켜 '첫 글자만 입력되는' 증상을
만든다. 이전 프로젝트에서 브라우저로 수동 재현해 찾았던 결함이다.

**영향** 린트 시간이 늘어난다. 두 린터를 함께 두지 않은 이유는 §9의
'비슷한 목적의 도구 중복 도입 금지'다.

**교체 조건** oxlint가 위 3개 규칙을 지원하면 재검토한다.

## D-002 · TypeScript 엄격 모드 + 추가 옵션

**결정일** 2026-08-01

**결정** `strict`에 더해 `noUncheckedIndexedAccess`,
`exactOptionalPropertyTypes`를 켠다. 스캐폴드 기본값에는 `strict`조차 없었다.

**근거** 이전 프로젝트에서 도메인 팩 스키마 오작성(배열 자리에 문자열)이
런타임 크래시로만 드러났다. 그 검출을 컴파일 타임으로 옮기는 것이 이 프로젝트의
핵심 목표 중 하나다.

**영향** `exactOptionalPropertyTypes`는 `{ x: undefined }`와 `{}`를 구분한다.
옵션 타입에 `| undefined`를 명시해야 하는 곳이 생긴다(실제로 3곳 겪음).
그 대가로 '속성이 없음'과 '값이 undefined임'이 섞이지 않는다.

## D-003 · 프로젝트 경로에 한글 사용 금지

**결정일** 2026-08-01

**결정** 저장소를 `C:\AgentQ-claude`에 둔다. 한글이 포함된 경로에 두지 않는다.

**근거** 폴더명을 정하기 전에 실측했다.

| 경로 | 모듈 수 | 결과 |
|---|---|---|
| 한글 경로 (최소 프로젝트) | 30 | 통과 |
| 한글 경로 (무거운 의존성) | 2,357 | **크래시 `0xC0000409`** |
| ASCII 경로 (**같은 코드**) | 2,357 | 통과 |
| 이전 프로젝트(한글 경로) | 2,437 | **크래시** |

코드는 같고 경로만 다른데 갈린다. vite 7·8 양쪽에서 재현되므로 버전 문제가
아니다. **작을 때는 멀쩡하다가 커지면 죽는다** — 이전 프로젝트가 이 함정을
7주간 못 잡은 이유다.

**영향** 폴더를 옮길 때 경로 제약을 지켜야 한다. `AGENTS.md` §14에도 적었다.

## D-004 · E2E 개발 서버 포트를 5180으로 고정

**결정일** 2026-08-01

**결정** Playwright `webServer`를 5180 + `strictPort`로 띄운다.

**근거** 5173은 Vite 기본값이라 다른 프로젝트의 dev 서버가 떠 있으면
`reuseExistingServer`가 **남의 앱을 테스트한다.** 실제로 겪었다 —
이전 프로젝트 서버에 붙어 전량 실패했다.

**관련 함정** 오래 떠 있는 dev 서버가 파일 쓰는 도중의 모듈을 빈 채로 캐시하는
일이 두 번 있었다. 단위 테스트는 통과하는데 브라우저만 백지가 된다.
E2E가 실패하면 **먼저 dev 서버를 내리고 다시 돌릴 것.**

## D-005 · 차트 라이브러리로 Recharts 도입

**결정일** 2026-08-01 (사용자 승인)

**문제** 데이터 조회·데이터 분석 에이전트가 추이·분포를 차트로 보여줘야 한다.
표만으로는 '공정 데이터 분석'이 성립하지 않는다.

**선택지**
- **Recharts** — 이전 프로젝트에서 이미 쓰던 것. React 선언형, SVG 기반
- Chart.js — canvas 기반이라 접근성·텍스트 추출이 약하다
- 직접 SVG — 축·툴팁·반응형을 다 만들어야 한다. 두 화면 때문에 감당할 비용이 아니다

**결정** Recharts. 이전 프로젝트에서 검증됐고 SVG라 E2E에서 값 검증이 가능하다.

**영향** 번들이 늘어난다(gzip 약 110KB). 차트를 쓰는 화면에서만 지연 로딩해
초기 번들에 들어가지 않게 한다. 제거 시 영향 범위는 해당 2개 화면이다.

## D-006 · 공통 실행 훅(useAgentRun)·화면 골격(AgentShell) 추출

**결정일** 2026-08-01

**결정** 문서를 입력으로 받는 에이전트의 공통 흐름을 훅과 화면 골격으로 뽑는다.

**근거** 요약·번역·검토를 **각각 만든 뒤** 같은 모양임을 확인하고 뽑았다.
표본 하나로 일반화하면 잘못된 골격이 나오고 둘이면 우연일 수 있다(가이드 §4).

**영향** 훅은 각 70~90줄에서 30~45줄로 줄었고, 추출 시점의 기존 테스트 56건은
한 줄도 고치지 않고 통과했다. 결과 타입은 제네릭으로 뒀다 — 요약 결과와 번역
결과는 공통 조상이 없고, 억지로 만들면 화면이 다시 좁혀야 한다.

**적용 범위** 문서 입력형 에이전트에만 쓴다. 대화형(챗봇)은 흐름이 달라
이 골격을 강제하지 않는다.
