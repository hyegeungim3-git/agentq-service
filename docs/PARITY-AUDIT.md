# 이전 데모 전수 대조 — 2026-08-08

사용자가 말하는 원본은 **`reb-ai-platform-v3`** 다. 그 소스(`genos-app/src/App.jsx`)의
관리자 메뉴를 파일로 떠서 재구축본과 하나씩 맞춰 봤다.

## 결과

| 처분 | 수 | 뜻 |
|---|---|---|
| 옮김 | 36 | 같은 것을 만들었다(이름이 달라도) |
| 합침 | 16 | 여러 메뉴를 한 화면 + 필터로 |
| 축소 | 2 | 일부만 옮겼다 |
| **미이관** | **6** | **합치기로 정한 것도, 일부러 뺀 것도 아니다. 그냥 없었다** |

**미이관 **5개**가 남았다(중대재해처벌법 대응은 2026-08-08에 옮겼다).**

재구축본은 44개. `60 = 36 + 16(→8화면) + 2 + 6`이고, 여기에 재구축본에서 새로
만든 것(평가 결과·에이전트 운영·앱 구성)이 더해져 44가 된다.

## 왜 여섯 개가 빠졌나 — 실측 대상이 달랐다

재구축 계획(`SCOPE-PLAN.md` §1)은 **`qagent-platform` 배포본을 눌러 가며** 쟀다.
사용자가 말하는 원본은 `reb-ai-platform-v3`다. 두 배포본은 같은 앱의 다른 시점이라
대부분 겹치지만 같지 않다 — 확인해 보니 배포본 쪽에 **아예 없는 메뉴가 다섯 개**였고,
있는데 못 보고 지나친 것이 **셋**이었다(그중 둘은 §6 재검수에서도 못 찾았다).

| 이전 데모(v3)에 있는 화면 | `qagent-platform` 배포본에 | 계획서에 |
|---|---|---|
| 카탈로그 · 리니지 | 없음 | 없음 |
| 코드스페이스 | 없음 | 없음 |
| 리더보드 | 없음 | 없음 |
| 답변 재현성 | 없음 | 없음 |
| 지식 증강 전략 | 없음 | 없음 |
| 예측 모델 운영 | **있음** | 없음 |
| 보안 아키텍처 | **있음** | 없음 |
| 중대재해처벌법 대응 | **있음** | 없음 |

이 여덟 중 리더보드는 평가 지표 화면이 다른 형태로 이미 담고 있고(REBUILD-NOTES §4),
코드스페이스는 일부만 옮겨져 있었다. 나머지 **여섯이 미이관**이다.

**교훈은 '더 잘 세자'가 아니다.** 사람이 눌러 센 목록은 셀 때마다 달라진다.
그래서 이전 데모의 메뉴를 파일(`docs/_v3-menu.json`)로 떠 두고, 리프마다 처분을
적게 했다(`scripts/parity.test.ts`). 처분이 없는 메뉴가 있으면 검사가 깨진다.

## 미이관 6개 — 무엇을 못 보여 주고 있나

전부 **이 제품의 차별점 쪽**이다. 표를 하나 더 그리는 화면이 아니라, 규제·운영에서
"그래서 그걸 어떻게 증명하느냐"에 답하는 화면들이다.

| 화면 | 그 화면에 있던 것 | 없으면 |
|---|---|---|
| **중대재해처벌법 대응** | 시행령 제4조 9개 호별 이행 상태·증빙, 위험성평가 이력 | 안전 관련 발주처에 법 대응을 못 보여 준다. AI 기본법 대응만 있고 짝이 없다 |
| **답변 재현성** | 과거 답변을 그때의 모델·색인·프롬프트 구성으로 재현 | "왜 지난달과 답이 다르냐"에 답할 수단이 없다. 감사 추적이 '기록은 남았다'까지만 간다 |
| **보안 아키텍처** | 망 경계를 넘는 흐름, 통제 적용 여부, 기한 만료 | 보안 검토에서 가장 먼저 요구받는 그림이 없다 |
| **지식 증강 전략** | RAG·CAG·TAG 라우팅 규칙 우선순위, 캐시 신선도 | "RAG 하나로 다 한다"로 보인다. 규정 조회에 매번 벡터 검색을 도는 낭비를 설명할 자리가 없다 |
| **카탈로그 · 리니지** | 자산의 원천→처리→소비처 계보, 표준화율 | 답의 출처를 데이터 자산까지 못 따라간다 |
| **예측 모델 운영** | 드리프트 감지, 재학습·승격 이력, 챔피언 vs 챌린저 | 모델을 배포한 뒤의 이야기가 없다 |
