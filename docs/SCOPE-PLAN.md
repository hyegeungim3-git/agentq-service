# 범위 계획 — 관리자 화면과 사용자 포털 잔여

> **결론부터**: 잘라내지 않는다. 이전 데모에 있던 것은 **전부 넣는다**(2026-08-02 지시).
> 다만 한 번에 다 만들 수 없으므로 **순서를 정한다.** 이 문서가 그 순서다.
>
> 범위를 정하기 전에 실측부터 했다. 기억으로 세면 반드시 빠진다.

## 1. 실측 결과

`_tmp-admin-inventory.mjs`로 배포본(`qagent-platform`)의 관리자를 전수로 눌러 봤다.

| | 값 |
|---|---|
| 관리자 메뉴 | **74개** |
| 그중 내용을 잰 것 | 42개 (나머지 32개는 측정 스크립트가 본문을 못 잡음 — 없는 화면이라는 뜻이 아니다) |
| 잰 42개의 합계 | 표 24 · 표 행 149 · 입력 244 · 버튼 432 · 차트 4 |
| 화면 하나 평균 | 본문 839자 · 버튼 10개 |

무게가 큰 화면(본문 1,000자 이상): 태스크플로우 빌더, 시나리오 빌더, 워크플로우,
RAG 파이프라인, 예측 모델 운영, 중대재해처벌법 대응, AI 품질 관리, 답변 재현성, AI 기본법 대응.

**사용자 포털에서 아직 안 넣은 것**(이전 대조 검수 기준):

- 사이드바 — 워크스페이스, 공지사항, 사용 가이드
- 헤더 — 알림 센터
- 일반 탭 — 라이브 지표(1×/10×/60×), 오늘의 업무 브리핑, 지도 인텔리전스
- 답변 — XAI 패널(판단 근거), 피드백(👍/👎)
- 설정 — 환경설정(다크 모드·표시 언어)
- 대화 — 영구 저장(지금은 세션 메모리만)

## 2. 정한 것 — 순서

사용자 포털을 먼저 끝내고 관리자로 간다. **포털이 실제로 쓰이는 화면**이고,
관리자는 그 운영 화면이기 때문이다. 운영할 대상이 완성되지 않았는데 운영 화면부터
만들면 두 번 고치게 된다.

| 단계 | 범위 | 화면 수 | 왜 이 순서인가 |
|---|---|---|---|
| **P0** ✅ | 사용자 포털 잔여 11종 | 11 | 가장 작고, 관리자가 관리할 대상이 여기서 확정된다 |
| **P1** | 관리자 셸 + 대시보드 4종 | 5 | 74개를 담을 골격. 여기서 목록·표·상태 표시 규칙을 정하면 나머지가 빨라진다 |
| **P2** | 운영·관리 (사용자·권한·로그·통계·콘텐츠) | 약 24 | 실서비스 개통에 반드시 필요한 것들. 사용자 관리 없이 서비스를 열 수 없다 |
| **P3** | AI 서비스 (가드레일·규제 대응·에이전트·워크플로우·RAG) | 약 26 | 이 제품의 차별점. 무게 큰 화면이 여기 몰려 있다 |
| **P4** | 인프라·개발 (모델 레지스트리·학습·평가·서빙·모니터링) | 약 19 | GPU·노드·파드는 **실제 클러스터가 붙어야** 값이 의미를 갖는다. 백엔드 연결 뒤가 맞다 |

합계 85종(포털 11 + 관리자 74).

### 왜 P4를 마지막에 두는가

P4 화면 대부분은 숫자판이다 — `Cluster CPU 5.32%`, `노드 3대`, `파드 5개`.
서버가 없으면 이 숫자는 전부 지어낸 값이고, 지어낸 값을 실측처럼 보여 주는 것은
이 저장소가 없애려는 바로 그것이다. 다른 단계는 fixture여도 **업무 로직**을 보여 주지만,
인프라 대시보드는 fixture면 **거짓 계기판**이 된다.

그래서 P4를 만들 때는 규칙을 하나 더 건다 — 아래 §3의 '실측 아님' 표시.

## 3. 모든 단계에 거는 완료 기준

지금까지 지켜 온 것을 그대로 적용한다. 화면 수가 많다고 기준을 낮추지 않는다.

1. **고른 것이 결과를 바꾼다.** 필터·탭·설정이 화면을 바꾸지 않으면 만들지 않은 것만 못하다.
2. **못 한 것을 드러낸다.** 빈 값·미정·권한 없음·집계 불가를 감추지 않는다.
3. **눌러도 아무 일 없는 항목을 만들지 않는다.** 이전 데모에 있어도, 뒤에 동작이 없으면
   동작을 만들어서 넣는다. 껍데기를 복제하지 않는다.
4. **데이터는 `shared/api` 경계를 지난다.** 화면이 fixture를 직접 읽지 않는다.
5. **fixture는 API 응답 형태.** 표시 문자열·색을 넣지 않는다.
6. **화면마다 테스트 + 탐지 확인.** 핵심 단언을 무력화했을 때 실제로 실패하는지 확인한다.
7. **실측 아님 표시(P4 전용).** 인프라 수치는 화면에 `서버 미연결 — 예시 값` 배지를 단다.
   서버가 붙으면 배지가 사라지는 것으로 연결 여부를 눈으로 확인할 수 있다.

## 4. 지금 정할 수 없는 것

관리자 화면의 절반은 권한 화면이다. 그런데 권한 규칙은 백엔드가 정한다
(`API-PROPOSAL.md` §3). 그래서 P2를 만들 때 다음 둘 중 하나를 택해야 한다.

- **(가)** 화면만 먼저 만들고 규칙은 서버 응답에 맡긴다 — 지금 기본값
- **(나)** 백엔드 회신을 기다렸다가 P2를 시작한다

(가)로 간다. 화면 구조는 규칙이 정해져도 크게 바뀌지 않고, 기다리면 아무것도 못 만든다.
다만 **권한 판정을 프론트에 하드코딩하지 않는다** — 서버가 준 값을 그리기만 한다.

## 5. 이 계획의 크기

한 화면에 테스트와 검증까지 붙이면 지금 속도로 세션당 3~6종이다.
85종이면 여러 세션에 걸친다. 한 번에 끝내겠다고 기준을 낮추면 이전 데모와 같은 것이
하나 더 생길 뿐이다.

진행 상황은 `AGENTS.md` §20에 단계별로 기록한다.
