# 인수인계 — AgentQ

가이드 `docs/ai-development-handoff-guidelines.md` §15 형식이다.
**이 저장소를 처음 받는 개발자가 코드를 다시 조사하지 않아도 되도록** 쓴다.

읽는 순서: 이 문서 → `AGENTS.md`(작업 규칙) → `docs/DECISIONS.md`(왜 그렇게 했나).
이전 데모와 무엇이 왜 달라졌는지는 `docs/REBUILD-NOTES.md`에 시간순으로 있다.

## 첫날 절차

```bash
git clone <repo> C:\AgentQ            # 경로에 한글이 들어가면 안 된다 — 아래 '주의사항' 참조
cd C:\AgentQ && npm ci
npm run verify                        # lint → typecheck → test → build
npx playwright install chromium
npm run e2e                           # 데스크톱·모바일 두 폭
npm run dev                           # http://localhost:5173
```

`npm run verify`가 통과하면 **받은 그대로 동작하는 상태**다. 통과하지 않으면 코드를
건드리기 전에 그것부터 본다 — 이 저장소는 게이트가 초록인 상태로만 커밋한다.

각 화면이 **먼저** 말한다. 이 문구들을 지우면 제품의 값어치가 사라진다.

## 설계 판단 — 왜 이 구조인가

전부 `docs/DECISIONS.md`에 D-001~D-013으로 근거가 있다. 이어받을 때 알아야 할 것 넷:

**1. 화면은 데이터를 직접 읽지 않는다.** `shared/api`를 통과한다. 지금은 fixture를
돌려주고, 서버가 정해지면 **그 안에서만** 바뀐다. 화면은 한 줄도 안 고쳐도 된다.

**2. 경계는 코드·id를 돌려주고 이름은 화면이 붙인다.** 경계가 `'공공'` 같은 라벨을
만들면 서버가 붙을 때 그 문자열까지 서버가 줘야 한다. 실제로 이 규칙을 어긴 자리가
있었고 2026-08-08에 고쳤다(`docs/RULE-AUDIT.md` V-2).

**3. 발주처는 데이터로 갈아 끼운다.** 화면을 복사하지 않는다. 새 발주처는
`src/fixtures/packs/`에 팩 하나를 추가하면 13종 에이전트와 관리자가 그 데이터로 돈다.
팩은 **고를 때 받는다**(D-013) — 정적 import로 되돌리면 넷이 첫 화면에 실린다.
그건 크기 문제이기 전에 테넌시 문제다.

**4. 코드는 사용자가 고르는 경계로 나눈다.** 관리자·에이전트·관리자 섹션이 각각
따로 내려받는다(D-012). **새 화면을 `App.tsx`에 직접 import하면 첫 화면 용량이
되돌아간다** — 검사가 막는다.

## 데이터 및 API

- **모든 데이터는 `src/fixtures/`.** 서버 없음
- 교체 지점: `src/shared/api/` 경계 함수 **118개**, `TODO(api-미확정)` 표시 **112개**
- 계약 제안서: `docs/API-PROPOSAL.md` — **프론트 제안이고 백엔드 확정 전이다.**
  확정된 것처럼 쓰지 말 것
- 기계가 읽는 명세: `docs/api/openapi.yaml`(생성물). **손으로 고치지 말 것** —
  `npm run api:spec`으로 타입에서 생성한다. 타입을 바꾸면 반드시 다시 생성해야 하고,
  안 하면 CI가 멈춘다(실제로 한 번 멈췄다)
- 주소별 사용처: `docs/api/USAGE.md` — 응답 형태를 바꾸기 전에 볼 것

**프론트가 정하지 않은 것**: 인증, 테넌시, 권한, 감사 로그, 보관 기간, 동시성 상한,
오류 코드. `docs/API-PROPOSAL.md` §3에 질문으로 남아 있다. 추측으로 채우면 '합의된 것'처럼
굳는다.

### 서버를 붙이는 순서

1. `docs/API-PROPOSAL.md`를 백엔드와 확정한다(§3 질문부터)
2. 경계 함수 하나를 골라 fixture 반환을 `fetch`로 바꾼다
3. 그 화면의 '서버 미연결 — 예시 값' 표시가 사라지는 것으로 진척을 확인한다
4. 로딩·빈·오류 상태는 **이미 화면에 있다.** 새로 만들 필요 없다

## 검증 결과 — 실행한 명령과 결과

2026-08-08 기준. 전부 실제로 실행한 값이다.

| 명령 | 결과 |
|---|---|
| `npm run lint` | 통과 |
| `npm run typecheck` | 통과 (strict + `noUncheckedIndexedAccess` + `exactOptionalPropertyTypes`) |
| `npm run test` | 541 통과 |
| `npm run e2e:app` | 278 통과 (데스크톱 1440 · 모바일 375) |
| `npm run e2e:a11y` | 58 통과 |
| `npm run budget` | 첫 화면 106KB gzip / 상한 200KB |
| `npm run build` | 통과 |

확인한 화면 크기: **375 · 1440**, 라이트·다크 양쪽.
사용자 흐름: 분야 선택 → 챗봇 문답 → 에이전트 13종 전수 → 릴레이 완주 → 관리자 56메뉴 전수.

**사람이 낭독기로 들은 적은 없다.** 접근성 검사 58개는 접근성 트리와 규칙 엔진을 본 것이고,
억양·중복 발화·읽는 순서는 사람만 판정할 수 있다. 대본이 `docs/A11Y-SCREENREADER.md`에
있고 기록지도 붙어 있다.

## 주의사항 — 다음 개발자가 확인해야 할 경계

### 이 저장소가 실제로 밟은 함정

| 함정 | 무슨 일이 났나 |
|---|---|
| **한글 경로** | 모듈이 늘면 `vite build`가 `transformed` 직후 **조용히 죽는다**. 작을 때는 멀쩡하다 — 이전 프로젝트가 7주간 못 잡았다 |
| **Windows에서 `npm install/uninstall`** | Linux 설치에 필요한 항목이 lockfile에서 빠져 CI의 `npm ci`가 멈춘다. 의존성을 바꾸면 **반드시** `gh workflow run lockfile.yml` |
| **`prettier --write`** | 이 저장소는 prettier를 쓰지 않는다(설정도 의존성도 없다). 돌리면 121파일이 통째로 바뀐다 |
| **헬퍼 복사** | 같은 함수의 사본이 넷까지 늘어난 적이 있다. 한 곳만 고치면 나머지가 **조용히** 안 고쳐진다 |
| **요약 마지막 줄만 읽기** | `grep "passed" \| tail -1`로 결과를 읽어 `2 failed`를 지나친 적이 있다 |

### 검사를 끄지 말 것 — 무엇을 막는지

각 검사는 **실제로 났던 결함**에서 나왔다. 느슨하게 바꾸면 그 결함이 돌아온다.

| 검사 | 막는 것 |
|---|---|
| `scripts/boundary.test.ts` | 의존 방향 역전, 화면의 fixture 직접 읽기, 경계의 라벨 생성 |
| `scripts/a11y-census.test.ts` | 표 행 머리글 누락, 이름 없는 정지점, 실행 시점에 생기는 라이브 리전 |
| `scripts/core-vocabulary.test.ts` | 코어에 특정 업종 낱말이 박히는 것(발주처 갈아 끼우기가 깨진다) |
| `scripts/design-tokens.test.ts` | 임의 색, 화면이 브랜드 색을 직접 읽는 것 |
| `scripts/readme-sync.test.ts` | README 숫자가 코드와 갈라지는 것 |
| `src/shared/api/contract.test.ts` | 코드와 API 제안서가 갈라지는 것(양방향) |
| `e2e/naming.spec.ts` | 메뉴 이름과 화면 제목이 갈라지는 것(다섯 번 갈라졌다) |
| `e2e/a11y-census.spec.ts` | 한 화면만 고치고 '전부 고쳤다'고 하는 것 |
| `npm run budget` | 첫 화면 용량이 되돌아가는 것 |
| `e2e/a11y-census.spec.ts` 팩 검사 | 고르지 않은 발주처의 업무 데이터가 내려가는 것 |

### 검사를 새로 쓸 때

**통과만 보지 말고 결함을 되넣어 실제로 실패하는지 확인한다.** 이 저장소에서
'통과하는데 아무것도 안 보는' 검사가 여러 번 나왔다 — 셀렉터가 어긋나 화면을 통째로
건너뛰면서 초록불이던 것, 규칙이 있는데 판정을 포기하던 것.

되돌릴 때는 문자열 치환으로 하고 `git checkout`을 쓰지 말 것 — 커밋 안 된 수정까지 날아간다.

## 기획자 확인용 (가이드 §16)

| 항목 | 상태 |
|---|---|
| 요구한 사용자 흐름이 모두 구현됐는가 | 사용자 포털·관리자 계획 범위 완료(`docs/SCOPE-PLAN.md`) |

| 임의로 추가된 기능·디자인이 없는가 | 없음. 추가는 `DECISIONS.md`에 근거 |
| 실제 데이터와 예시 데이터가 구분돼 있는가 | 예 — 화면마다 '서버 미연결 — 예시 값' 표시 |
| 새 라이브러리·구조 변경이 사전 합의 없이 들어갔는가 | **한 건 있었다** — recharts 제거(D-011). 절차를 어긴 사실을 기록했고 되돌릴 수 있다 |
| 테스트·빌드 결과가 구체적으로 기록됐는가 | 위 '검증 결과' |
| 미구현·정책 결정 사항이 숨겨지지 않았는가 | 위 '남은 작업' |
| 변경 파일과 실행 방법이 정리돼 있는가 | 위 '첫날 절차'·'주요 변경 파일' |
| 이어받을 인수인계 내용이 있는가 | 이 문서 |
