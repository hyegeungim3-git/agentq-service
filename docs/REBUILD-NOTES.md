# 재구축 기록 — 무엇을 왜 다르게 만들었나

> 이전 데모(`qagent-platform`)를 `agent-rules` 가이드에 맞춰 다시 세운 기록이다.
> **무엇이 달라졌는지, 왜 그렇게 했는지**를 남긴다. 결정의 배경은 `DECISIONS.md`,
> 앞으로 만들 것은 `SCOPE-PLAN.md`, API 제안은 `API-PROPOSAL.md`에 있다.
>
> 이 문서는 작업이 끝날 때마다 갱신한다. 낡으면 지운다.

## 1. 왜 다시 만들었나

이전 데모는 백엔드 없이 전부 mock으로 도는 시연물이었다. 그대로 실서비스로 가면
**API를 붙이는 순간 화면을 전부 다시 써야 한다.** mock이 UI 표시용 형태였기 때문이다.

```js
// 이전 데모
{ label: '수집 항목', value: '4,380건', sub: '...', tone: 'base' }
```

`'4,380건'`은 이미 포맷된 문자열이고 `tone: 'base'`는 색이다. 서버는 둘 다 주지 않는다.
서버는 `4380`을 주고 천 단위 구분과 색은 화면이 정한다.

목적은 하나다 — **실제 API를 붙일 수 있는 형태로 다시 세우는 것.**
화면·콘텐츠는 자산으로 가져오되 데이터 형태는 옮기지 않는다.

## 2. 구조가 달라진 점

| | 이전 데모 | 지금 |
|---|---|---|
| 언어 | JavaScript | TypeScript strict (`noUncheckedIndexedAccess`·`exactOptionalPropertyTypes`) |
| 화면 파일 | `UserApp.jsx` 2,173줄 → 모듈 분리(진행 중이었음) | 영역별 분리 (`app`/`pages`/`widgets`/`features`/`entities`/`shared`/`fixtures`) |
| 데이터 | 화면이 mock을 직접 읽음 | **`shared/api` 경계를 반드시 통과** — 서버는 이 안에서만 교체 |
| mock 형태 | UI 표시용 문자열·색 | **API 응답이 될 수 있는 형태**(원시 값·코드·ID) |
| 스키마 | 없음 (런타임에 깨짐) | `entities/*/model.ts` 타입 — fixture가 타입을 만족해야 컴파일 통과 |
| 린트 | 없음(명령은 있으나 CI에 없어 오류 71건 누적) | ESLint + react-hooks v7, **CI 게이트** |
| 테스트 | 없음 | 단위/화면 190여 건 + E2E 110여 건(데스크톱·모바일) |
| CI | 없음 | lint → typecheck → test → build → E2E, 통과해야 배포 |
| 배포 | 수동 | GitHub Pages, verify 통과분만 |

### 경로 별칭을 쓰는 이유

`@shared` 같은 별칭은 취향이 아니라 **의존 방향을 눈에 보이게** 하려는 것이다.
`../../../`는 어느 층에서 어느 층을 부르는지 숨긴다. `shared`가 특정 페이지를 알면 안 된다.

### `<main>`은 화면이 갖는다

셸은 `<nav>`와 배치만 맡는다. 셸에도 `<main>`을 두면 화면마다 main이 둘이 되어
보조기기가 본문을 못 찾는다.

## 3. 화면이 달라진 점 — 공통 원칙

이전 데모와 가장 크게 다른 것은 **AI가 못 한 것을 드러낸다**는 점이다.
에이전트마다 "이것만은 숨기면 안 되는 것"을 하나씩 정하고 화면이 먼저 말하게 했다.

| 화면 | 숨기지 않는 것 |
|---|---|
| 문서 요약 | 압축률과 원문 대조 안내 |
| 번역 | 역번역 일치도가 낮은 문장, 사전에 없어 번역 못 한 문장 |
| 사전 검토 | 심각도 높음이 남아 있으면 결재 상신을 권하지 않음 |
| 챗봇 | 근거를 못 찾으면 답을 지어내지 않음 + 출처 원문 열람 |
| 보고서 | 사람이 채워야 하는 칸(`pendingFields`) |
| 회의록 | 담당·기한 미정 항목, 논의되지 않은 안건, 명단에 없는 발언자 |
| 지식 검색 | 필터에 걸려 빠진 건수 — '없다'와 '안 보여 준다'는 다르다 |
| OCR | 신뢰도 낮은 줄, 설정 때문에 나빠졌다는 사실 |
| 데이터 조회 | AI가 가정한 조건, SQL로 못 옮긴 표현 |
| 기준정보 표준화 | AI로 해결 안 되는 660건과 표준화율 상한 86% |
| 데이터 분석 | 분석에 쓰이지 못한 데이터(적용률 71%) |
| 안전관리계획 | 대책 뒤에 남는 잔여 위험 |
| 오케스트레이션 | 끝까지 갔어도 사람이 확인할 지점 합계 |
| 관리자 대시보드 | 실측이 아니라 예시 값이라는 사실 · 주의 상태의 사유와 조치 · 파드 재시작 횟수 |
| 관리자 메뉴 | 아직 안 만든 화면 19개를 감추지 않고 '준비 중'으로 표시 |
| 사용자 목록 | 접속 이력이 없는 계정 · 상태 변경이 저장되지 않았다는 사실 |
| 승인 관리 | 며칠 기다렸는지 · 신청 사유를 안 적었다는 사실 |
| 할당량 | 한도 초과분 · 집계 기준 시각 · 무제한 계정을 0%로 그리지 않음 |
| 접근 로그 | **로그에 남지 않는 것** — 목록만 보면 '여기 있는 게 전부'로 읽힌다 |
| 접근권한·차단 | 만료돼 더 이상 막지 않는 규칙 |
| LLM 설정 | 모델을 왜 껐는지 · 이 모델로 나가는 답변이 무엇인지 |
| 신뢰성 관리 | **아직 안 잰 효과** — 0으로 세면 효과가 없어 보이고 평균이 무너진다 |
| 신뢰성 관리 | 가드레일을 껐을 때 무엇이 통과하게 되는지 |
| AI 품질 관리 | 손봐야 하는 답변의 비율 · 사용자 피드백이 이 브라우저 것뿐이라는 사실 |
| 이용 이력 | 질의 본문을 남기지 않는다는 사실과 그래서 못 하는 것 |
| 이용만족도 | **답하지 않은 사람 수** — 평균은 답한 사람만의 평균이다 |
| 이용 통계 | 평균 응답시간이 성공한 요청만 센 값이라는 것 |
| 통계 리포트 | 지금 못 만드는 항목과 그 이유 |
| 통합 로그 | 접근 로그와 같은 데이터라는 사실 · 질의 본문 미보관 |
| 사용량 | 지금 속도면 며칠 뒤 한도에 닿는지 · 금액이 없는 이유 |
| 콘텐츠 관리 | 여기 있는 것이 곧 포털에 보이는 것이라는 사실 |
| HR 연계 | **처리하지 못한 퇴직** — 그 계정은 지금 접속이 열려 있다 |
| API 관리 | 키를 화면에 두지 않는 이유 · 베타·중지 API가 왜 그런지 |
| 프롬프트 | 바꿨을 때 무엇이 달라지는지 |
| 연계 SW | 끊기면 무엇이 멈추는지 (정상인 것도 함께) |
| 가드레일 | **경고만 하고 통과시킨 건** — 그건 실제로 나갔다 |
| AI 기본법 | 이 화면이 법적 판단을 내리지 않는다는 것 · 판정이 안 끝났는데 운영 중인 시스템 |
| 사업장 지표 지도 | 값이 없는 사업장과 그 이유 — 평균이 전사 평균이 아니라는 사실 |
| 라이브 지표 | 실측이 아니라 예시 값이라는 사실 |
| 판단 근거 | 이 답변만으로 결정하면 안 되는 이유 |

### 두 번째 원칙 — 고른 것이 결과를 바꾼다

이전 데모에는 **결과를 바꾸지 않는 설정**이 여럿 있었다. 옮기면서 전부 실동작으로 고쳤다.
아래는 재구축 과정에서 실제로 발견해 고친 것들이다.

| 발견 | 무엇이 문제였나 |
|---|---|
| 발주처 선택 | 공공을 골라도 제조 문서(`프레스_작업표준서`)가 그대로 나왔다 |
| 데이터 분석 | 무엇을 골라도 같은 불량률 추이가 나왔다 (대상도 PDF·음성이었다) |
| 번역 언어 | 일본어·중국어를 골라도 영어 번역문이 나왔다 |
| OCR 설정 | 언어·표 추출·처리 모드·결과 형식이 결과를 바꾸지 않았다 |
| 보고서 | 문체·분량이 없었고 직접 입력 칸도 없었다 |
| 사이드바 항목 | 워크스페이스·공지사항·사용 가이드가 눌러도 아무 일이 없었다 |

## 4. 의도적으로 다르게 만든 것

가이드가 "미확정 API의 운영 계약을 임의로 만들지 않는다"고 해서, 이전 데모에 있던 것 중
**지어내야만 옮길 수 있는 것**은 형태를 바꿨다.

| 이전 데모 | 지금 | 이유 |
|---|---|---|
| 보안 게이트웨이 설정 탭 | 데이터 취급 현황 | 운영 정책이 미정이라 설정 화면을 만들면 다 정해진 것처럼 보인다. 지금 사실인 것만 적고 미정 개수를 먼저 말한다 |
| MCP 호출 로그(grpc 주소·토큰 수) | 각 단계가 부르는 데이터 경계 함수 | 인프라 주소를 지어내지 않는다. 서버가 붙으면 그 자리가 엔드포인트가 된다 |
| 파일 업로드(성공) | 검사까지 동작, 전송은 실패 | 서버가 파싱해야 본문이 나온다. 성공한 척하면 남의 문서 분석 결과를 보여 주게 된다 |
| 발주처 4종 모두 선택 | 제조만 선택 가능, 나머지는 '업무 데이터 준비 중' | 업무 데이터가 하나뿐인데 고르게 두면 고르는 행위에 의미가 없다 |
| 지도(지리 좌표 위 표시) | 배치 도식 + '실제 지리 좌표 아님' | 좌표 데이터가 없다. 지도처럼 보이는데 위치가 틀리면 그게 제일 위험하다 |
| 표시 언어 전환(전면) | 화면 틀만 전환, 콘텐츠는 원문 유지 | 규정 조항을 기계 번역하면 그게 원문인 줄 알고 인용하게 된다. 원문을 보여 주는 이유와 같은 이유다 |
| 관리자 메뉴 74개를 전부 노출(빈 화면 포함) | 만든 것과 준비 중을 구분해 표시 | 감추면 기능이 없는 줄 알고, 껍데기를 두면 만든 줄 안다. 눌렀을 때 무엇이 언제 오는지 말한다 |
| 서비스 상태 `Warning` 배지 | 사유 + 조치 문장 | 상태를 아는 것과 조치할 수 있는 것은 다르다 |
| 계정 정지·승인이 동작하는 관리자 | 조회는 동작, 변경은 실패를 그대로 알림 | 화면에서만 바꾸면 정지시킨 줄 알고 닫는데 그 계정은 살아 있다. 업로드와 같은 처리(D-009) |
| 정확도 향상 `-` 표기 | '측정 전' + 평균에서 제외 | `-`나 `0`은 '효과 없음'으로 읽힌다. 안 잰 것과 효과가 없는 것은 다르다 |
| 신뢰성 관리의 RAG 파이프라인 탭 | 두지 않음 — 지식 관리(P3)에서 다룸 | 같은 것을 두 화면에 두면 어느 쪽이 진짜인지 알 수 없게 된다 |
| 이용 이력에 질의 본문 표시 | 본문 없음 + 왜 없는지 | 접근 로그가 '질문 본문은 남기지 않는다'고 말하고 있었다. 두 화면이 다른 말을 하면 어느 쪽이 사실인지 알 수 없다. 보관 여부는 백엔드가 정한다(§3-7) |
| 접속 로그를 두 화면에 각각 보관 | 한 데이터를 두 관점으로 | 사용자 관리는 계정 관점(거부 먼저), 통합 로그는 운영 관점(종류별). 복제하면 같은 시각의 같은 행위가 서로 다르게 적힌다 |
| 콘텐츠 관리가 자체 목록을 가짐 | 포털과 같은 자원 | 따로 두면 '여기서 고쳤는데 포털에 안 나오는' 상태가 생긴다 |
| 콘텐츠 관리의 설문 탭 | 안내만 — 서비스 분석에서 다룸 | 같은 것을 두 화면에 두면 어느 쪽이 진짜인지 알 수 없다 |
| 시스템 설정 하위 4개 | 화면 2개 + 관리 홈 진입점 | '공지사항'은 콘텐츠 관리와, '시스템 모니터링'은 대시보드 시스템 현황과 같은 화면이었다. 두 벌 만들지 않고 관리 홈 카드가 그 화면으로 간다 — 진입점은 그대로 남는다 |
| API 키 목록·재발급 | 키를 아예 표시하지 않음 | 목록에 있으면 화면을 여는 사람 모두가 모든 키를 갖게 되고, 화면은 캡처되고 공유된다. 잃어버렸으면 재발급이 정답이다 |
| 가드레일 규칙 목록(두 화면) | 신뢰성 관리=설정, 가드레일=이력 | 같은 목록을 두 화면에 두면 어느 쪽이 진짜인지 알 수 없다. 이전 데모의 가드레일 메뉴는 눌러도 대시보드로 떨어지는 죽은 메뉴였다 |
| 차단 이력에 걸린 원문 표시 | 종류와 건수만 | 개인정보를 가리려고 만든 규칙의 이력에 그 개인정보가 그대로 있으면 앞뒤가 안 맞는다 |

### 다크 스킨을 화면마다 칠하지 않은 이유

`dark:` 접두사를 화면마다 붙이는 방법 대신 **팔레트 변수 한 벌만 뒤집었다**
(`src/index.css`). Tailwind v4는 모든 색 유틸리티가 `var(--color-*)`를 참조한다.

접두사 방식은 새 화면이 생길 때마다 빠뜨리고, 빠뜨린 자리는 밝은 채로 남는다.
변수 방식은 앞으로 만들 관리자 74개 화면도 자동으로 따라온다.
값은 반대편 색조를 그대로 써서 밝기 대비를 보존한다 — 임의로 어둡게 칠하면 대비가 무너진다.

## 5. 재구축 중에 잡은 결함

이전 데모에서 넘어온 것이 아니라 **다시 만드는 과정에서 생겼다가 잡힌 것**들이다.
같은 실수를 반복하지 않기 위해 남긴다.

| 결함 | 어떻게 드러났나 |
|---|---|
| 한글 경로에서 `vite build`가 조용히 죽음 | 모듈 30개는 통과, 2,357개에서 크래시. ASCII 경로에서 같은 코드가 통과해 원인 확정 |
| CI `npm ci` 실패 | Windows에서 만든 lockfile에 Linux용 항목이 빠짐. CI 환경에서 lockfile을 만들어 해결(D-008) |
| E2E가 남의 dev 서버를 테스트 | 포트 5173이 흔해서. 5180 고정 + strictPort |
| 차트 E2E가 두 번째에만 통과 | dev 서버가 요청 시점에 컴파일. CI는 preview 빌드로 전환(D-007) |
| 사이드바 중복 렌더로 라벨 끊김 | 같은 `id`가 DOM에 둘 생겨 모바일 워크스페이스 선택이 이름 없는 콤보박스가 됨. E2E가 잡음 |
| 무른 단언 | 검색 방식 테스트가 요약 문구를 비교하고 있었다. 방식 이름·소요 시간은 결과가 같아도 달라진다 |
| 라이브 지표가 1배속에서 안 움직임 | 관측 간격을 10분으로 잡아 전체 재생에 90분이 걸렸다. E2E가 60배속에서도 안 끝나는 것으로 드러났다. 1분 간격으로 줄여 1배속에서도 변화가 보이게 했다 |
| 렌더 중 `Date.now()` | `useRef(Date.now())`가 렌더마다 다른 시작 시각을 만들 수 있었다. ESLint 순수성 규칙이 잡았고, 기준점을 effect에서 잡도록 고쳤다 |
| 사전으로 옮기며 문구가 어긋남 | 사이드바 여는 버튼을 '사이드바 펼치기'로 새로 썼는데 기존 이름은 '사이드바 열기'였다. 모바일 진입점 20곳이 한꺼번에 막혔다. E2E 전체가 잡았다 — 문구를 옮길 때는 새로 쓰지 말고 그대로 옮긴다 |
| 지도 타일 색이 다크에서 안 보임 | 타일 배경을 고정 `rgba()`로 칠해 팔레트를 안 따라갔다. 변수를 섞도록(`color-mix`) 바꿨다 |
| 새 경계 함수 6개가 제안서에 빠짐 | 관리자 API를 만들고 문서를 안 고쳤다. **계약 드리프트 테스트가 잡았다** — 이 테스트를 만든 이유가 이것이다 |
| 정렬 테스트가 무름 | 가장 오래 기다린 승인 신청이 fixture 맨 앞에 있어, 정렬을 지워도 테스트가 통과했다. **탐지 확인이 잡았다.** fixture를 접수순으로 바꿔 정렬이 일을 하게 만들었다 |
| 메뉴 이름과 화면 제목이 다름 | 메뉴는 `접근권한·차단`, 제목은 `접근권한 · 차단`이었다. 같은 것을 두 번 쓰면 갈라진다. **HR 연계에서 같은 실수를 반복했고 E2E가 또 잡았다** |

### 검증 방식 — 탐지 확인

테스트를 쓴 뒤 **결함을 일부러 다시 넣어 실제로 실패하는지 확인**한다.
통과만 보면 단언이 무른지 알 수 없다. 이 습관으로 위 '무른 단언'을 찾았다.
